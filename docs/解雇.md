请在现有 AI Company 项目中增加完整的“解雇员工 / Employee Offboarding”能力。

核心原则：

解雇员工绝对不能直接 DELETE Employee。

员工被解雇以后，他的：

聊天记录
会议记录
工作记录
Goal / Task 参与记录
代码提交
文档
Artifact
OpenClaw Session 历史
招聘记录
入职记录

都必须保留。

解雇只是：

员工不再属于当前公司的在职员工，
停止 Agent Runtime，
回收权限，
释放工位，
处理未完成工作，
最后从虚拟办公室离开。

==================================================
一、用户如何发起解雇
==================================================

支持两种入口。

第一种：

点击办公室中的员工
→ 打开员工手机/详情
→ 更多
→ 解雇员工

第二种，也是更符合本产品理念的方式：

直接和 HR 对话。

例如：

“苏晴，把张晨解雇掉。”

HR 应该理解这是 Employee Termination Request。

不能让 LLM 直接删除员工。

应该生成结构化命令：

TerminateEmployeeCommand

然后进入正式离职流程。

==================================================
二、解雇前必须展示影响
==================================================

例如用户准备解雇：

科技内容作者

系统需要先检查：

正在进行的 Meeting
拥有的 Artifact
自己的 Workspace

工位
未读消息

弹出确认：

正在执行任务：2
负责 Goal：1
未完成稿件：1
占用工位：F2-Desk-04
Agent Runtime：OpenClaw

并提供：

○ 自动交给主管重新分配
○ 先暂停，稍后处理
○ 取消任务

Workspace 如何处理：

○ 归档保留（默认）
○ 保留为只读
○ 删除

第一版默认：

任务交给主管重新分配
Workspace 归档
聊天和工作历史永久保留。

==================================================
七、OpenClaw Agent 如何处理
==================================================

因为现在每一个 Employee 对应一个 OpenClaw Agent。

所以解雇员工时需要执行：

Employee TERMINATING

↓

停止新的 Runtime 请求

↓

取消/等待当前 OpenClaw Run

↓

Disable OpenClaw Agent

↓

撤销 Company Tool 权限

↓

撤销 Workspace 写权限

↓

停止对应 Sandbox

↓

归档 Runtime 信息。

不要直接马上删除 OpenClaw Agent 数据。

建议状态：

runtime_status：

ACTIVE
DRAINING
DISABLED
ARCHIVED

解雇完成：

ARCHIVED

这样未来仍然可以查看：

这个员工以前用了什么模型
调用了多少 Token
执行过什么任务
产生过什么 Artifact。

==================================================
八、Sandbox 与 Workspace
==================================================

解雇后：

普通员工绝不能继续访问自己的 Sandbox。

默认流程：

停止 Docker Sandbox

↓

Workspace：

/company-data/employees/zhangchen/workspace

移动/标记为：

/company-data/archive/employees/zhangchen/

或者通过数据库设置：

workspace_status = ARCHIVED

默认只读。

不能默认删除。

因为里面可能存在：

代码
文章
设计稿
测试报告
资料
Git Commit
其他公司资产。

这些属于公司工作成果，而不是随着 Agent 删除一起消失。

==================================================
九、公司权限立即回收
==================================================

Employee 进入 TERMINATING 后就应该停止获得新的敏感权限。

最终 TERMINATED 后全部撤销：

company_send_message
company_create_task
company_update_task
company_request_meeting
company_publish_artifact
Shell
Browser
Filesystem RW
MCP
Codex
Claude Code
其他 Harness

如果有独立 Token / Credential：

必须撤销。

不要只依靠“Prompt 告诉 Agent 你被解雇了”。

权限必须由系统层真正禁止。

2. 标记未完成事项。
3. 整理需要交接的 Artifact。
4. 不再启动新的任务。

例如：

内容：

当前工作

未完成内容

但注意：

Agent 只是负责整理交接内容。

是否解雇、权限什么时候撤销：

由 Company Backend 决定。

不能由 Agent 自己决定。

==================================================
十七、不要直接删除 Employee
==================================================

除非是：

测试数据
误创建数据
管理员进行数据清理

否则正常“解雇员工”绝对不能调用：

DELETE /employees/{id}

应该：

POST /employees/{id}/terminate

或者：

TerminateEmployeeCommand。

DELETE Employee 和 Terminate Employee 必须是两个完全不同的概念。

==================================================
最终原则
==================================================

招聘是：

Candidate
→ Hire
→ Employee
→ Agent Runtime
→ Workstation
→ 进入公司

解雇是反向生命周期：

Employee
→ Stop New Work
→ Handover
→ Task Reassignment
→ Disable Runtime
→ Revoke Permissions
→ Archive Workspace
→ Release Workstation
→ Walk Out Of Company
→ TERMINATED

员工不能凭空出现。

员工也不能凭空消失。

请基于现有：

Employee
HR
Agent Runtime
OpenClaw
Workspace
Sandbox
Workstation
Floor
Movement
Message
Task
Goal
Event Store

实现统一 Employee Offboarding Workflow。

不要推翻当前架构，也不要把解雇实现为数据库 DELETE。
